# Qualifying a consumer's native migration

A compiled module is a candidate. Qualify it against a retained execution
before selecting it as the consumer's default. This process applies to a new
runtime ABI, a changed observation catalogue, or promotion of interpreted
source identities into native code. It does not certify complete game or
hardware compatibility.

## Keep the identities separate

Bind the original runtime, diagnostic helpers, original captures, composed
profile, emitted module, descriptor, executable and adjacent libraries to
their exact reviewed bytes. Diagnostic scripts can be independently pinned
without changing the runtime ABI. A runtime/compiler digest does not cover
every diagnostic script; record those additional bindings explicitly.

Relocating a harness can change deferred sibling-helper paths. Exercise the
actual planning branches during preflight, bind their nested dependencies,
and check each injected helper's intended origin. An authenticated import
closure alone does not exercise a helper loaded only by a later route action.

Preserve original capture ABIs, checkpoint origins and per-input hit counts.
Historical profile totals describe the catalogue's inputs, not work performed
by a new replay. Record emitted identities and actually executed identities
separately. See [observation profiles](OBSERVATION_PROFILES.md).

Metadata relocation requires a specific, reviewed relation to the exact
historical bytes and consumed fields. Do not introduce a general path or
source-hash allowance when a consumer updates its public toolchain metadata.

An intentional device-response change needs a new behavioral baseline. Old
controls and scene goals can seed discovery, but their guest states, clock
endpoints, images and audio are not expected values for the new profile.
Record a complete canonical run under the new recipe, then qualify replay
against that same recipe. A pre-command metadata relation must stop applying
as soon as the changed device behavior is exercised.

Audit inherited navigation shortcuts before discovery. Skipping an input or
adding a finishing action requires current scene and game-state evidence;
an older full-image hash, CPU snapshot or elapsed-frame count is not a new
profile's semantic precondition. Inspect before the optional action. If the
scene differs, retain the refusal and establish a reviewed bounded route;
replacing the expected image hash alone does not establish that route.

## Retain a closed discovery and semantic control sequence

Use checkpoint reconnaissance in the qualified package for routine same-recipe
coverage and harness debugging. Reuse its baseline instead of replaying a known
prefix for each experiment. Reserve complete reset qualification for a changed
recipe or a finished candidate milestone. Each package still needs its own
checkpoints; this workflow does not permit cross-build fingerprint edits.

Use finite host, controller, frame-step, instruction and tick bounds. Preserve
the original wire journal, actual process result, source capture and observed
endpoints. Bind a closed journal to its completed receipt before archiving;
hashing the current file alone does not recover historical provenance.

Seal each literal frame request with [semantic steps](SEMANTIC_STEPS.md).
Active progress polls can occur at different instructions and in different
numbers. Retain them and validate their bounded progress; compare settled
endpoints separately. Timestamp-free old journals cannot prove elapsed wall
time. A consumer must measure candidate durations rather than invent old ones.

Retain and verify every input operation and explicit assist. Use the
[typed paused-write relation](PAUSED_WRITES.md) with full RAM readback,
source-generation checks and complete code-footprint exclusion. A successful
validator grants no authority for another write, retry or different value.
Keep game addresses, route choices and semantic assertions in the consumer.

Checkpoint reconnaissance must retain branch ancestry. Bind each fork to its
actual imported file and observed starting state. A pickup on one fork and
an equipment screen on another do not establish a pickup-to-equip sequence.
Validate the closed process and control receipts, then qualify each named
scene goal through explicit game-state and image evidence.

## Prove the native conversion

Rebuild through the supported consumer interface, then run from the declared
starting condition. A checkpoint continuation is not a fresh reset. Compare
strict settled CPU/device observations, complete relevant RAM, source
identities, images and digital audio under the declared comparison scope.

For each identity promoted from fallback, prove:

```text
candidate native hits = baseline native hits + baseline interpreted hits
candidate interpreted hits = 0
candidate executed identity set = baseline executed identity set
```

Identity includes logical PC, all MPRs, physical fetch addresses and original
instruction bytes. Aggregate totals alone can hide an identity substitution.
Check block-transfer tier counters separately. Compiled catalogue entries
that never execute remain unqualified by that replay.

A complete new-profile run may already execute entirely natively using a
retained module. If its source keys are covered and its interpreted count is
zero, qualification need not force a module rebuild or claim a promotion
gain. Preserve the new execution capture as proof. Compose it into a source
catalogue only when required; redundant replay captures consume contribution
and byte capacity without establishing additional reachable code.

For an unchanged state codec, an offline comparison of complete serialized
machine cores can strengthen the endpoint check. Validate each original
archive, schema, ABI, declared lengths and body digest first. Name and prove
each permitted tier-counter conversion; keep every other byte exact. Never
write or import a modified checkpoint to manufacture cross-module equality.

## Test checkpoints and paced output independently

A timed-out discovery can retain valid retired source observations without
qualifying its route. Keep the failed receipt intact. If a later window
continues from an owned checkpoint, bind the checkpoint file, save response,
reported state and original source identity before admitting that window.
Checkpoint reconstruction is proof work, not another contribution to the
compiler profile or the route's instruction totals.

When joining windows from separate processes, namespace request IDs and
checkpoint names. Compare each window's newly retired source-key counts
against its own origin, then sum admitted, nonoverlapping contributions.
Preserve the original raw captures and their ABI labels. A joined reference
must be labeled as such; it is not a single cold run. The final candidate
still needs its own fresh replay from reset. An unsaved historical endpoint
supports only its retained observations, not an invented complete-core
comparison.

Live [TCP source-counter pages](DEV_SERVER.md) are not encoded captures: their rows contain
`source_id`, PC, MPR, physical addresses and hit counts, without instruction
bytes. Final captures contain the bytes and use a different ordering. Never
recover missing bytes from current memory or join these formats by array
index. Use the closed encoded capture for canonical source-key comparison;
preserve live pages separately as instrumentation from their own process.

Checkpoints bind their own module and machine recipe. Create a candidate's
own checkpoint; restore it in a fresh process, test immediate complete-file
equality, then execute the same finite suffix and compare complete continued
files and source-key retirements. Imported prefix work is not newly executed
work. Validate origin, window and lifetime counters separately.

Read-only continuations can inherit nonzero debug-write counters. Compare
them with the saved origin and require no new writes; do not require their
lifetime totals to be zero. Bind the source context and the host's derived
file identity separately when checking a checkpoint envelope.
Join `checkpoint.audio_origin` to the actual imported checkpoint's save reply,
including pending PCM and source WAV frames. Keep that origin fixed through
the continuation; it is distinct from the current process's WAV sink count.
Require exact keys and integer types as well as values: Python's ordinary
equality accepts `False` for `0`. Check running polls too when they contribute
to the audio proof.

Digital PCM equality and SDL queue accounting answer different questions.
For a paced test, retain active observations and distinguish newly generated
PCM from imported pending PCM. Check the queue balance:

```text
initial pending + newly generated = submitted + final pending
```

File-output bookkeeping is also separate from synthesis. If a reference has
no WAV sink and a candidate records a capped WAV, prove the exact serialized
sink-field relation from source, actual commands, save replies and each
checkpoint's own identity. Compare all other host and guest bytes strictly.
Do not drop the whole host prefix to make the files compare.

The desktop host deliberately clears queued presentation audio on pause and
resume. Paused shutdown can also drain pending guest PCM into the paused
host. Therefore zero synthesis loss and zero active overflow do not imply
zero host drops across an intentional pause. Bind each transition and its
queue counters; do not excuse unplanned active clears as pause behavior.
Positive accepted submissions beyond the imported queue establish fresh
device submission, not physical playback, listening parity or device timing.

Preserve failed criteria and raw evidence. A later source-backed policy
adjudication or new test must remain separate from the failed original test.
Receipt bookkeeping errors require explicit hash-bound corrections derived
from retained observations; a later verification is not an original check.

## Retained full-route consumer evidence (ABI 26)

The Ys III ABI 26 migration's fresh native replay reaches the retained route's
terminal stair room after **102,802 frames**, with **3,122,661,937 native and
zero interpreted instructions**. The discovery run's **3,433 interpreted
instructions**, including **68 block transfers**, become native. The new
catalogue preserves **57,545** old identities and adds **207**, for **57,752**
compiled identities; this replay executes **54,610** distinct identities.
The route retains the consumer's explicit `cd-unknown-status=gear-good`
compatibility policy. Zero interpreted CPU instructions does not establish
implemented semantics for those unknown CD commands.

All 16 baseline/native checkpoint pairs pass an independent complete-core
comparison. Only five named execution-tier counters change under their exact
conversion equations; all other serialized core bytes match. Original files
retain separate module fingerprints and are never modified for loading.

The route contains 300 explicit assisted RAM writes and six nonempty automated
semantic gates across 33 case boundaries. Retained images and controls also
support miner dialogue, an assisted deeper-boss defeat/rewards and movement
on the terminal stairs. This is assisted finite route coverage, not campaign
completion, hardware certification or proof that every case name was asserted.

Two candidate-owned checkpoint suffixes each execute **60 new frames,
1,851,616 native and zero interpreted instructions**. Immediate round trips
and complete continued checkpoint files match byte for byte. These suffixes
are separate from the fresh full replay and from paced output qualification.

A separate 120-frame paced suffix executes **3,703,226 native and zero
interpreted instructions**, generates **88,456 new PCM frames**, and quits
naturally. All 119 active observations report zero host drops. The planned
pause clears 729 queued presentation frames, and shutdown separately drains
the remaining seven guest PCM frames into the paused host. The imported 39
frames are accepted on resume. These phase counts preserve exact queue
conservation and establish fresh SDL submissions; they do not establish
lossless listening or physical playback. The prior zero-drop-across-pause
assertion remains failed rather than being relabeled by this new test.

That earlier ABI 26 migration left the runtime/compiler sources and state
codec unchanged. No fresh Geargrafx comparison was claimed for it: that milestone qualified
consumer composition, native dispatch, semantic replay and checkpoint use
against retained behavior; existing independent device comparisons retain
their original scope.
The earlier [ABI 27 invalid-CD profile](CD_UNKNOWN.md) checks have their own
independent device matrix and bounded consumer tests. Those results alone
did not promote this retained route into a new ABI or response policy.

## ABI 27 native migration

The new catalogue retains all 57,752 earlier compiled identities and adds
250, for 58,002. Its seven original inputs keep their ABI18/26/27 labels,
raw hashes, own checkpoint origins and individual contributions. The profile
contains 239,346 contributions in 121,417,027 bytes; embedded original raw
captures total 43,513,842 bytes. All existing parser bounds remain unchanged.
Reconstruction captures and native verification captures are excluded.

The reference joins an original reset prefix to an admitted 126-frame tail
from its own exact-build checkpoint. Reconstruction proves the cutoff and
creates that owned file; its repeated work is not counted again. The original
timed-out discovery remains failed. All 309 assists are typed RAM writes,
checked against every original, compiled and subsequently fetched code alias.

The candidate's separate fresh native process starts from reset and passes
**104,745 frames**, with **3,209,517,525 native and zero interpreted
instructions**. All 53,516 executed encoded source identities conserve their
individual retirements. The reference's 6,899 interpreted retirements become
native; its block-transfer interpreted count was already zero. The replay
contains 108,460 sealed records and 5,523 bounded steps, with 33 RAM case
outcomes and retained scene observations.

All 26 source/native checkpoint comparisons validate each file against its
own module identity before comparing the machine core. Only the five named
execution-tier counters change. The 24 ordinary saves also keep all host
bytes exact; the link and final comparisons permit only the source-backed
eight-byte WAV-sink count relation and keep the other 52 host bytes strict.
No source checkpoint is rewritten or imported into the new module.

Its endpoint is the actual green Alcaino frontier combat ledge, rather than
the older ABI26 diagonal stair-room scene. Earlier wizard defeat, rewards,
equipment and assisted boss checks retain their own observed scope. This is
finite assisted compatibility evidence, not campaign completion.

A prior native attempt stopped after frame 104,619 on an unused live-counter
snapshot passed to an encoded-capture helper. Its failed receipt remains
intact. An owned-checkpoint 126-frame debug tail passed before the corrected
fresh reset replay. The fix removes that unused query and explicitly refuses
nonzero tail-query routes; it changes no runtime semantics or guest checks.

A separate read-only extension loads the successful native run's own final
checkpoint and executes **432 new frames, 13,795,134 native instructions and
zero fallback**. Its 7,799 encoded identities conserve the source window's
counts, converting seven interpreted retirements to native. Main and
extension together execute 53,528 distinct identities. The extension adds
12 identities absent from the main run: five newly compiled variants and
seven retained catalogue entries. All 250 additions to the catalogue execute
across these two tests: 245 in the main run and five only in the extension.
The extension has no new RAM writes; its inherited 309 writes remain visible.
Its final whole-core comparison uses the source lifetime interpreted count
of 6,906, distinct from the seven new window retirements, and keeps all host
bytes exact because both new final files have no WAV sink.

Two candidate-owned fresh-process continuations each execute 60 new frames,
**1,836,171 native and zero interpreted instructions**, covering 1,912 encoded
identities. Immediate round trips and complete continued checkpoint files
match byte for byte, as do full RAM, images and per-key hits. Each child's
imported audio provenance matches its actual source checkpoint save reply.

A separate paced 120-frame fork executes **3,672,293 native and zero
interpreted instructions**. Its guest PCM accounting is
`40 imported + 88,457 new = 88,487 submitted + 10 pending`.
All 119 active polls show zero host drops and no unplanned clears. The planned
pause clears 687 presentation frames, leaving 87,800 accepted frames; at
least 87,760 are newly generated, including a conservative 86,742 newly
nonzero frames. Shutdown submits and drops the remaining ten pending frames
separately without changing synthesis or its hash. All 120 step polls and
paused observations retain exact typed imported-audio provenance.

The real loaded SDL modules match the adjacent packaged DLL, with no SDK
`PATH` workaround. These tests establish finite native execution, exact-build
checkpoint repeatability and fresh digital output submission. They do not
establish listening parity, physical device timing or complete hardware
compatibility. No additional shared runtime/compiler or state-codec change
was needed for this consumer migration.
